# 自动询价与报价回收

本机采购流程已经接入邮件 Agent。控制邮箱发送请购单后，Agent 按物料分组联查供应商和邮箱，逐家生成询价邮件及 CSV 附件，分批自动发送。供应商直接回复并回传填好的附件，校验通过后报价自动写入 SQLite；控制邮箱会收到处理回执。

## 控制邮箱如何发起

- 发件人：`config.yml` 中 `control.allowed_senders` 配置的控制邮箱，例如 `owner@example.com`。
- 收件人：`config.yml` 中 `mail.address` 配置的 Agent 邮箱，例如 `agent@163.com`。
- 主题：自由填写，例如“采购申请”。不要求 `[AGENT]` 前缀。
- 附件：一份现有格式的请购单 CSV 或 XLSX，不是本目录的询价单模板。保持原请购单的14列表头，每行一个独立请购单编号，状态编号填10。
- 正文直接用普通中文描述，不需要口令或YAML。例如：

```text
请按附件请购单发起询价，向对应供应商发送询价单，收到报价后自动入库。
```

请求也可以直接写在新邮件主题里，正文允许留空。例如主题“请按附件请购单发起询价”，附上请购单即可。Agent合并主题和当前正文理解请求；正文中的“只查看”“暂不发送”等限制同样生效。正文为空的Re/回复/转发邮件不会重复执行原标题中的旧动作，需要写明本次请求。

如邮件还有其他CSV/XLSX附件，在正文说明“请使用附件《请购单表.xlsx》发起询价”。首次处理会导入请购单并自动排队发送；重复发送相同请购单不会重复询价。已有请购单编号但内容不同会报冲突。

## 查询和邮件问答

从同一控制邮箱发到Agent邮箱，直接提问即可，不需要附件：

```text
查一下请购单20261030AL的报价信息。
哪些供应商已经报价？哪些询价仍在等待回复？
查询供应商SUP0001的信息。
解释一下含税单价、税率和最小起订量是什么意思。
```

模型将请求识别为请购询价、数据库查询、解释问答或澄清。报价查询、请购单、供应商、询价发送进度及订单查询读取实际SQLite记录，并标明匹配条数和展示范围；日期以Asia/Shanghai为准。一般问答由已配置模型生成，没有实时联网检索。回复Agent的回信可延续同一控制者邮件对话。

只有明确要求实际请购/询价、同时附上合法请购单时才创建询价。“只查看附件，暂不发送”等请求不会触发发送。供应商报价来信继续按询价编号和登记邮箱核对，不会被当作控制邮件。控制邮件中的权限、路由、允许动作都来自本机配置；模型不能指定任意收件人、SQL或执行代码。

## 本机配置

当前`config.yml`已设置自然语言模式。配置示例：

```yaml
control:
  mode: natural_language
  allowed_senders: ["owner@example.com"]
  actions: [inquire, query, answer, update_data]
  update_tables: [suppliers, material_groups, supplier_groups, statuses, requisitions, quotations, orders]
  update_max_rows: 1000
  query_limit: 50
  answer_chars: 12000
procurement:
  enabled: true
  max_sends_per_cycle: 10
```

邮件正文无需包含任何配置或密钥。白名单邮件使用自然语言控制；非白名单不能执行控制动作。若需旧版任务管理，可在`control.actions`额外启用create/update/pause/resume/delete/list，仍按原有任务权限和收件人校验。`structured`仅作为旧协议兼容模式。

## 用邮件更新业务表

现在可直接从控制邮箱更新数据库中的现有记录，例如：

```text
请按附件供应商表，按供应商唯一编号更新供应商邮箱，只修改邮箱列。
把供应商SUP0001的邮箱改为new@example.com。
把请购单PR001的需求日期改为2027-06-01。
把报价单QT001的报价价格更正为128.50，税率改为13%。
```

供应商、物料分组、供货关系、状态、请购单、报价单和订单都提供对应字段更新能力，由`control.update_tables`限制。指定唯一编号及新值就是更新授权，信息齐全时直接执行，不再另发“是否允许更新”的确认邮件。只要求查询或预览、明确说暂不修改时不会写入。

按附件批量更新时，可使用CSV/XLSX完整表或仅包含“唯一编号＋需要更新列”的简表。比如更新供应商邮箱只需“供应商唯一编号、供应商邮箱”两列；完整表中的公司名、称呼不会跟着修改，除非正文明确要求。

整个批次在事务内校验并回读核对，回信报告匹配数、更新数、未变化数和变更明细。每次修改保留控制者、源邮件、时间以及旧值和新值，重复处理同一邮件不重复执行。可以发送“查询今天的数据更新记录”查看审计记录。

找不到编号、重复编号、非法邮箱、错误数量或关联不存在时整批不写入；不会自动新增供应商、删除记录或纠正邮箱域名。空白附件单元格不覆盖旧数据，清空可空字段须在正文明确提出，例如“清空供应商SUP0001的称呼”。

修改供货关系时，附件使用“供应商唯一编号、原物料分组唯一编号、新物料分组唯一编号”三列，或正文明确原分组和新分组。记录唯一编号、报价归属和系统运行队列不能通过通用更新改写。

已有有效询价的请购单保留需求快照，需求变化使用新请购单编号；已被订单引用的报价不能原地覆盖。供应商邮箱更新后，后续新询价使用新邮箱，已发询价和原待核对发送记录保留原收件邮箱；不会因更新资料自动重发历史询价。

Agent 每轮最多发10封供应商询价，其余保留队列，后续轮次继续发送；无需另发发送命令。原90行请购单对应94家供应商，整份发送会产生94封供应商询价。先试少量行时，请只发送这些行；后续不能以相同请购单编号覆盖它们。

## 询价模板

- `询价单模板.csv`：正式使用的20列表头，UTF-8带BOM。
- `询价单示例.csv`：需求信息已填、报价栏留空的演示。
- `供应商报价填写示例.csv`：同一演示的8个报价栏填写方式。
- `询价邮件模板.txt`：实际询价邮件的正文结构。

上述编号和价格仅用于演示。实际每封邮件会生成新的询价编号，按收件供应商填入相应物料；不要将演示报价当作真实报价发回。程序用 `procurementdb/templates.py` 中同一套字段和文案生成正式询价。

前12列是询价编号、报价单编号、请购单编号、供应商编号、物料分组、物料编码、物料名称、需求型号、单位、需求数量、需求日期和品牌。

后8列由供应商填写：

| 字段 | 填写方式 | 示例 |
| --- | --- | --- |
| 报价型号 | 实际报价产品的完整型号 | M-01 |
| 报价价格 | 每申请单位的单价，只填数字 | 128.50 |
| 报价数量 | 本次可供应数量，大于0 | 10 |
| 交货期 | 实际交货日期 YYYY-MM-DD | 2027-05-01 |
| 最小起订量 | 非负数字 | 1 |
| 币种 | 三位币种代码 | CNY |
| 含税标识 | 1为含税，0为未税 | 1 |
| 税率 | 百分比或0到1小数；零税率填0 | 13% |

报价价格按含税标识说明税费口径，不自动推断运费或其他附加费。本轮仅询价和记录报价，不创建订单。

## 供应商如何回信

1. 使用供应商表登记的完整邮箱地址回信，保留 `+supplier001` 等标签；不将子地址合并为基础邮箱。
2. 直接点击“回复”，保留原主题里的 `[询价编号:RFQ-…]`，`Re:` / `回复:` 前缀均可。
3. 填写收到的附件后8列，保留前12列和表头；回传唯一一份 CSV 或 XLSX 表格。正文写“报价见附件”即可。
4. 可以只回传已报价的行；无法报价的行删除并在正文说明，不能用空白价格或0数量表示报价。
5. 修订报价使用新报价编号，例如原编号后加 `-R2`。相同编号不同价格不覆盖原报价。

邮件主题示例：

```text
Re: [询价编号:RFQ-20261031-12AB34CD56EF] 物料询价
```

仅发自由格式正文、图片或PDF不会自动作为报价入库。错误附件、错询价编号、错供应商、缺少税率等情况会归为待核对并通知控制邮箱；供应商应发一封新的更正邮件。已经成功导入的同一封来信即使重复同步，也不会重复写入。

## 查看与维护

在 `email-agent-lite` 目录使用已安装依赖的 Python：

```powershell
python agent.py procurement-status
python procurement_db.py check
```

数据库为 `data/procurement.sqlite3`。IMAP/SMTP 仍使用原配置。询价发件队列以 SQLite 为准，控制回执和报价处理通知沿用原 JSON 发件记录；工作台可看到这些回执和归档的供应商邮件。

停止自动流程时先停止服务，再执行 `python agent.py procurement-disable`；恢复使用 `python agent.py procurement-enable`。发送中断且SMTP结果不明确时保留 `uncertain`，不会自动重发，需要人工核对。启用之前的历史控制邮件不会补发询价。

目前158项本地自动化测试通过，包含只写主题时的查询、问答、请购和数据更新，以及主题正文合并、空白回复防重复执行等。实际模型接口验证了请购、报价查询、问答及按供应商编号批量更新邮箱。启用前的历史控制邮件不会自动重放。
