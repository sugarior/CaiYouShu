# 演示初始业务数据

`procurement.json` 来自原 `data/procurement.sqlite3` 的七张业务表，保留业务编号、物料信息、供货关系等字段。当前包含 100 家供应商、32 个物料组、133 条供货关系、7 个状态、180 条请购单，报价和订单均为空。

供应商真实邮箱在快照中替换为占位值，初始化时使用账号配置的演示收件邮箱。快照不含邮箱授权码、模型配置、登录信息、源邮件引用、邮件归档或历史询价/发件队列。各账号从同一份初始数据创建独立 SQLite，后续写入互不共享。

按演示要求，源库中状态为 20 且尚无报价、订单的请购单在初始快照中恢复为状态 10；本次共恢复 90 条。源库保持不变，其余业务状态保留。`original_business_sha256` 标识去除供应商真实邮箱后的原业务内容，`sha256` 校验用于初始化的快照内容。

需要从原单账号库更新快照时，在项目目录使用虚拟环境 Python 执行：

```sh
python demo_seed.py data/procurement.sqlite3
```

这是离线导出，不收发邮件。更新快照会影响之后新注册的账号；现有数据版本不同的账号不会被无条件覆盖，需要显式设计迁移。

旧 `v1` 简化演示库升级到本快照时，平台在启动 Agent 前完成一次迁移：先用 SQLite 备份 API 写入账号 `data/seed-backups/`，再补齐业务数据；仅移除能逐字段识别且没有实际业务引用的旧演示样例。现有修改、询价、报价、订单、邮件和审计记录保留；已有统一供应商邮箱修改会沿用。迁移报告记录在 `runtime_metadata.demo_seed_migration`，重复启动不重复迁移。
